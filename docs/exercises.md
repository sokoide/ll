# 自分で書けるか確認する課題

完成版を読むだけで終えず、別ブランチまたは作業コピーで変更する。最初に文法と期待結果を書き、その後にlexer→parser→AST→評価器→compiler/VMのうち必要な箇所を選ぶ。

## 1. 単項マイナス（小）

`put(-1+2);`、`put(2*-3);`を受理し、それぞれ1、-6を出力させる。`put(--2);`を許すか先に決める。

- unaryの文法をtermとprimaryの間に挿入する。
- FIRST(expr)がどう変わるか書く。
- `-2*3`のASTを紙に描く。
- lexerで符号付き数値にまとめず、`1-2`と区別できるようにする。
- VMへNEGを加えるか、既存命令へ落とすか選ぶ。

合格条件: `-`だけの入力はエラー。既存の二項減算と優先順位が壊れない。

## 2. if文（中）

まずelseなしの`if(cond){stmts}`を追加する。次に`else`を任意にする。ブロックのスコープ規則を先に決める。

- stmtのFIRSTに何を足すか。
- 省略可能なelseを1トークンで決められるか。
- VMの前方ジャンプを何本使うか。

合格条件: 真偽両方、空ブロック、入れ子、閉じ忘れ、ifとwhileの組合せを両エンジンで確認する。ブロックを必須にすることで、括弧なし構文のdangling else問題を持ち込まずに進める。

## 3. 関数呼出しを式にする（設計）

`primary = IDENT | IDENT '(' args ')' | ...`はその形のままではIDENTで選択肢が重なる。共通のIDENTを先に消費する文法へ左因子分解する。

合格条件: IDENTの直後に`(`がある場合と、`+`や`;`の場合を、バックトラックなしで選べる文法と擬似コードを書く。関数の実行自体は追加しなくてよい。

## 4. エラーの説明（読解）

`put(1+);`、`while(a<){}`、`a=1 2;`、`while(1){`のそれぞれについて、停止する関数、current、期待するトークンを実行前に予測する。

合格条件: `-dump tokens`と実際のエラーで予測を照合する。構文エラーと`put(1/0);`の実行時エラーを混同しない。

## 振り返り

- 各parse関数は何を消費し、何をcurrentに残すか。
- 反復のどこで必ず入力が進むか。空にできる規則を無条件で反復するとどうなるか。
- 同じ演算結果でもASTが違う場合をテストできるか。
- 言語仕様、構文規則、AST構造、実行方式を分けて説明できるか。

設計の確認用に[ヒント](hints.md)を用意している。
