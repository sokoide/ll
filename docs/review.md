# 教材レビューと今回の改善

対象読者はGoで通常のアプリケーションを書けるSWE。目標はLL(1)の規則から自分で再帰下降関数を作り、構文エラー・優先順位・結合方向をテストできること。VMはその後の応用とする。

| 以前の問題 | 学習上の影響 | 改善 |
| --- | --- | --- |
| 最初からwhile・スコープまで提示 | 1トークン先読みの核が見えにくい | 整数1個から6ステップの作業用文法を用意 |
| AST評価器しかない | VMとAST走査を混同しやすい | compilerとスタックVMを別ファイルへ追加 |
| 文も式もexpression型 | 構文上の役割が型から読めない | statementとexpressionを分離 |
| STRINGが算術primaryに入る | 構文と意味の不要な例外が多い | put_itemでのみSTRINGを受理 |
| エラーに内部トークン番号を表示 | 期待した文法要素を特定しにくい | NUMBER、IDENT、';'等の名前を表示 |
| 評価値中心のテスト | ASTの誤った結合を見逃し得る | ASTの形、トークン列、bytecodeを固定値で検証 |
| 左再帰の説明だけで実装手順がない | 読解から自力実装へ進みにくい | 呼出し追跡、FIRST/FOLLOW、課題、ヒント、合格条件を追加 |
| 評価器に多量のログと重複処理 | AST評価の制御フローを読みづらい | 評価器を整理し、演算・変数規則だけ両エンジンで共有 |

文法変更はSTRINGの位置だけ。`a="x";`、`put("x"+1);`、`while("x"){}`は以前の実行時エラーから構文エラーになる。有効だった数値プログラムと文字列の直接出力は維持する。

先頭ゼロの直接出力、正の整数だけが真、未定義変数が0、while全体で1スコープという参照元の仕様は残し、LL(1)の必須条件ではないことを明記する。これらを一般的な言語処理系の規則と誤解しないこと。

自動テストは完成版の機能と教材中の具体例を確認する。学習者が実際に自作できるかという教育効果は、読者による試行では未検証。小さい作業用パーサーは各ステップで読者自身が作る設計で、完成版CLIのモード切替による別実装ではない。
