# Step 6: ASTからスタックVMへ

LL(1)の学習はStep 5までで一度区切れる。ここでは同じASTを別の実行方法へつなぎ、パーサーが「実行せず構造を返す」理由を確認する。

```text
source → lexer → tokens → LL(1) parser → AST
                                         ├→ tree evaluator → output
                                         └→ compiler → instructions → VM → output
```

[evaluator](../../pkg/minilang/eval.go)はASTノードを再帰的に訪問する。VMはASTを知らず、PC（次に実行する命令のアドレス）と整数のオペランドスタックを持つ。関数呼出し用のGoのスタック、変数のスコープスタック、VMのオペランドスタックは別物。

## まず算術だけを実装する

文法は増やさない。Step 3の式ASTを後行順（左の子→右の子→親）で命令にする。

```sh
printf 'put(1+2*3);' | ./mini-compiler -dump bytecode
```

```text
0000 PUSH 1
0001 PUSH 2
0002 PUSH 3
0003 BINARY '*'
0004 BINARY '+'
0005 PRINT_INT
0006 NEWLINE
```

| 実行した命令 | スタック（右端が先頭） |
| --- | --- |
| PUSH 1 | `[1]` |
| PUSH 2 | `[1,2]` |
| PUSH 3 | `[1,2,3]` |
| BINARY '*' | `[1,6]` |
| BINARY '+' | `[7]` |
| PRINT_INT | `[]` |

`BINARY`ではrhsを先にpopし、次にlhsをpopして`lhs op rhs`を計算する。加算だけでは順序の間違いを発見できない。`20-5-3`と`24/4/2`を必ず試す。

## 変数と制御フローを加える

| 命令 | スタック効果 | 動作 |
| --- | --- | --- |
| PUSH literal | +1 | 整数字面をintへ変換して積む |
| LOAD name | +1 | 変数値を積む。未定義なら0を作る |
| STORE name | -1 | popした値を変数へ代入 |
| BINARY op | -1 | 2値をpopし、結果1値をpush |
| PRINT_INT | -1 | popした整数を出力 |
| PRINT_TEXT text | 0 | 字面を直接出力 |
| NEWLINE | 0 | 改行 |
| ENTER_SCOPE / LEAVE_SCOPE | 0 | 変数スコープを作成／破棄 |
| JUMP address | 0 | PCをaddressへ変更 |
| JUMP_IF_FALSE address | -1 | popした値が0以下ならPCを変更 |

どの式もスタックに1値を残し、どの文も実行前後でスタックの深さを変えない。この2つをコンパイラの不変条件にする。

whileは次の配置になる。

```text
ENTER_SCOPE
start:
  条件の命令
  JUMP_IF_FALSE exit
  本体の命令
  JUMP start
exit:
LEAVE_SCOPE
```

`start`は後ろ向きジャンプなのでその場で分かる。`exit`はまだ存在しないため、一度仮アドレスでemitし、本体の生成後に書き換える。これをバックパッチという。[compileStmt](../../pkg/minilang/compiler.go)の`exit`と`c.code[exit].arg`を追う。

ENTER_SCOPEをstartより前に置く理由は、全反復で同じローカル変数を使うため。`JUMP_IF_FALSE`の飛び先がLEAVE_SCOPEを通ることも確認する。

## 実装課題と合格条件

1. 手書き命令列`PUSH 20, PUSH 5, BINARY '-', PRINT_INT`を実行するVMを作る。
2. 式ASTから命令列を生成する。括弧はASTをまとめた時点で役割を終え、専用命令は不要。
3. LOAD / STOREを加える。
4. whileの前方ジャンプをバックパッチする。
5. AST評価器とVMで同じプログラムの出力が一致することを確認する。

```sh
./mini-compiler -dump bytecode < examples/count.mini
./mini-compiler -engine tree < examples/count.mini
./mini-compiler -engine vm < examples/count.mini
go test ./pkg/minilang -run 'TestBytecode|TestVM|TestExamples'
make testall
```

ゼロ除算、出力先エラー、再実行、入れ子のwhileも試す。命令ごとのPC更新では、まずfetchしPCを1増やしてから実行し、ジャンプだけがPCを上書きする。

このVMのbytecodeはGo structのメモリ内命令列で、バイナリ保存形式ではない。コンパイラが生成した命令だけを実行し、外部の任意bytecodeの読込み・検証、最適化、GC、関数呼出しは扱わない。整数演算と変数スコープの意味規則はAST評価器と共有しているので、両者の一致テストに加えて固定の期待出力も検証する。
